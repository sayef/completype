How completion and ranking work

The database is a bucket.

completype is a library, not a service. Storage is the only shared component.

  • Create-only commits. Version N + 1 is written with If-None-Match, so concurrent writers never corrupt each other.
  • Readers follow by themselves. Engines load only changed, immutable segments and switch versions atomically.
  • No hop on the hot path. Queries run inside your process, on memory-mapped segments.

Serverless deployment

One catalogue, many views.

Tenants, locales, listeners, promotions and takedowns are small indexes stacked on the shared catalogue, overriding it per document id, without a copy. Five layers over 200,000 titles answer in 0.2 ms at the median.

Python
import completype

db = completype.connect("s3://my-bucket/completions")
txn = db.begin()
txn.append("songs", docs)
txn.commit()

engine = db.engine()   # follows new versions
engine.complete("danc", ["songs"])
Rust
let database = Database::open("./data", Vec::<(String, String)>::new()).await?;
let mut txn = database.begin().await?;
txn.append_documents("songs", docs, [])?;
txn.commit().await?;

let engine = Arc::new(Engine::new());
let replica = Arc::new(Replica::new(database, IndexOptions::default()));
replica.sync(&engine).await?;
let _follower = replica.follow(&engine, Duration::from_secs(5));
engine.complete(&["songs"], "danc", 10)?;

The full quick start

Questions

What does serverless mean here?

There is no completype server. The engine is a library in your process, and the database is a set of files in a bucket or directory. Your application is deployed however you like; completype adds no service to it.

How is it different from Elasticsearch, Typesense or Meilisearch?

Those are search servers for documents with many fields, filters and facets, and every query crosses the network. completype does autocompletion only, inside your process. Many applications use both: a search server for the results page, completype for the box.

How do several writers avoid conflicts without a server?

Through the store. Each commit creates the next manifest create-only, so exactly one writer wins each version and the others retry. For high write rates, a single ingestor elected by an expiring lease commits queued change sets in order.

How fresh are completions after an update?

Engines sync every sync_every seconds (5 by default), so a committed transaction appears within a few seconds; engine.sync() loads it at once.
